Storm re-booking desk Minneapolis–Saint Paul (MSP)

A winter storm has cancelled flights out of Minneapolis–Saint Paul, and every affected customer needs a new plan. Workers scale up with the queue. Each customer gets an offer: the rules engine's first choice, then reroutes if they say no. Every record must end with an accepted offer or with a person: none lost and none decided twice, even while workers crash, messages arrive twice and AWS throttles calls. Several runs can share the system at once, from any tab, and each works on its own copy of the records.

Multi-tenancy: runs sharing this deployment

Every run is a tenant. Runs share the queues, the workers and the database capacity, but each run has its own copy of the records and its own settings. Admission control keeps the total inside the free-tier budget.

  • Own data: each run works on its own copy of the records in its own partition (RUN#<id>), so runs never read or overwrite each other's records.
  • Fair share of workers: each run's messages carry its run id as their group, so SQS fair queues stop a big run (a load test) from starving a small one.
  • Own settings: rejection, crash, poison and throttle settings travel on each run's own messages and never apply to another run.
  • Shared budget: at most a fixed number of runs and records are active at once, across chaos, integration and load runs. Requests over the limit get a clear 429.
  • Scoped actions: a cancel stops only its own run. A repeated start with the same client token returns the first run, and a stale client can't change a finished run.
  • Scoped recovery: the dead-letter sweeper and orphan re-queue write only into the run that owns the record.

Rules vs agent: rerouting with a live model

Both arms use the same 500 generated customers and can run side by side. Each customer will only accept one particular offer, and most of them hinted at it on an earlier call (a note on their record). On every reroute the rules arm makes the next offer in the rules engine's fixed order. The agent arm asks Claude Haiku on Bedrock to pick the next offer from what's left, using the record, the note and what was already turned down. The first offer always comes from the rules engine. The note and the hidden preference are synthetic, made for this demo.
